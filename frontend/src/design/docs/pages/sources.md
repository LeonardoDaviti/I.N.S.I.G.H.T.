# Sources

Code: `pages/SourcesConfig.tsx`, `components/sources/*`, `components/SourceSettingsEditor.tsx`, `components/connections/*`, `components/ops/*`.

## Purpose

Where sources are managed, and the only home of ingestion jobs and secrets (P7): add, group, tune, switch off or delete sources; see whether ingestion runs; set provider credentials.

## Entry & URL

- `/settings/sources`, from the `sources` nav word, ⌘K (Sources, Ingestion) and every source or track name in a reading view (P8).
- Tabs as `?tab=`: none = **sources**, `connections` (`&provider=<id>` opens that provider), `ingestion` (`&sub=archive|jobs|logs` for its views, `&job=<id>` for one job, `&sub=archive&source=<id>` for one source's backfill).
- Sources tab view in the URL: `?q=`, `?status=`, `?group=track|kind` (none, one flat list, is the default; the old `?group=platform` groups by kind); the old `?status=backoff` opens Failing, `?sort=name|kind|posts|lastPost|added` (status is the default) and `?dir=asc|desc` (left out while it is the column's own: name and kind ascending, the rest descending; status descending is worst first; within a status, and in every column, ties go A to Z by name). The legacy `?tab=health` opens the flat list with its `?status=`; old or unknown values (`sort=success`, `group=status`) fall back to the defaults.
- `?source=<id>` opens that source's detail sheet; closing the sheet removes it, and Back closes the sheet. `?track=<id>` groups by track, scrolls to the track's group and briefly highlights it. An unknown id shows the list with a quiet note ("That source no longer exists"), no error page.
- `/ingestion[/:tab]` (the old ingestion page) redirects here, to the view that holds that tab, carrying the query. Dev-only `?data=worst|empty|one|huge`.

A site's home page with no feed (issue 0041) offers its own blog or news page instead, the one with the most articles: a small "Follow stripe.com/blog: 269 articles" button (already previewed: "Following stripe.com/blog" heads the panel; the pasted address stays the source's name), the other candidates under a quiet "Other pages on this site" disclosure; no such page with articles: "This is the site's homepage: it may pick up product pages, not articles." over "Follow this page instead", and again in the panel. No readable article: "This page's articles can't be read without a browser (it builds them with JavaScript)." and Add stays disabled; "This feed is already in your sources" too; at its foot, the bookmarklet line, for saving one page instead, `pages/shell.md`). A template with a field (GitHub Trending, Nitter, Telegram RSS) says under it what is already added: "Added: All languages, Python". "Add several…" beside the address label (issue 0035) turns the dialog into "Add several sources": "← One source", an "Addresses (one per line)" box (up to 50) and an "Import OPML" file link that fills it from the file's `xmlUrl`/`htmlUrl` outlines (one parent shared by all of them becomes the suggested new track; INSIGHT's own export brings back its names and page watching); "Find feeds" looks each up through the feed finder four at a time, "Looking for feeds… 3 of 12" with "Stop", rows appearing as answers arrive: the address, then the feed's title and address (several: a radio list), "INSIGHT reads it directly", "No feed: follow the page (12 articles)" (previewed automatically; a home page: "No feed: follow stripe.com/blog (269 articles)", or the page with the homepage warning), "Already in your sources" / "Already in this list", "Nothing readable" or "Could not look for a feed; added as typed"; a tick per row (already and unreadable ones unticked and disabled), "Track for all" (No track, the tracks, "New track…" with a name), and "Add N sources", each fetched now as a single add is ("Added" or "Could not add: …" per row; the dialog closes when all were added). Cancel closes it mid-way (while adding: after the one in flight). Under the list, a quiet "Export sources (OPML)" link downloads `GET /api/sources/export.opml`.
- **The Saved source** (issue 0031): created by the first saved page, named "Saved", kind "Saved pages", status Scheduled and the note `pages you save` (never `never fetched`). It is never fetched, so never due or failing. Its sheet says "The pages you save from any site. Never fetched by itself." in place of Fetch now, keeps Name, Tracks and Show in Main feed, and has no cadence, archive or fetch delay. Read posts reads what you saved; its posts are unread until read.
- **Tabs:** lowercase underline `sources / connections / ingestion`.
- **sources tab:** a toolbar (search field, status chips Enabled · Disabled · Failing (backoff included), then, only while they have sources, Unavailable · Due · Scheduled · Tidy up, each with a count; the Group select: No grouping · Track · Kind (the Kind column's names, so a subreddit groups with Reddit whatever its address); below md a "Sort: Added ↓" button that opens the column sort buttons as a row), then column headers that sort (Name, Kind, Posts, Last post, Added, Status: a press sorts, a second press reverses, the active one is pressed and shows ↑/↓), then one dense list. Flat by default; grouped, the groups have sticky, collapsible headers and, for a track, a ⋯ track menu (Fetch now on phones, Rename…, Show in Main feed, its check read from the track's sources: ✓ all in, – some, none blank; a press puts them all in or, when all are in, takes them out; Delete track…); the sources in no track come last, after a thin divider, without a header. A row, 36px: checkbox (revealed on hover/focus or once anything is selected), status glyph, name (opens the sheet), kind, posts, last new post, added, a status note (what happens next or went wrong; a broken source the source doctor looked at reads "Broken: replacement found" or "Broken: no replacement found", issue 0036; a source that went quiet reads "Quiet: last post Mar 4", one never opened "Never opened: 214 posts", issue 0046), a read arrow (opens the reader on the source; revealed on hover/focus, always on touch), on/off switch. On a phone: glyph, name, posts, read, switch; never a URL.
- **Tidy up** (`?status=tidy`, issue 0046): the list filtered to the sources marked quiet (its fetches work, but nothing new for 30 days and more than 3× its own usual gap) or never opened (20 posts or more, added 30 days ago or more, none opened, put in Later or kept); a broken or disabled source has neither mark. A marked row there shows **Keep** and **Remove…** after its note: Keep drops the mark (the row leaves the view) until it is still true 90 days later; Remove… asks and deletes as any delete does. Nothing is removed or muted without that click. Empty: "Nothing to tidy up: no source went quiet or goes unopened."
- **Bulk bar** (sticky bottom, while rows are selected): count, on/off, Add to track, Remove from track, Show in Main feed (on or off), Delete, clear (Esc).
- **Source sheet** (from the right, 32rem): name, its kind (as the Kind column names it) and "Read posts", the address with copy, a health summary (a due source reads `due · next check in 37m`, the scheduler's next tick, or `due · scheduler not running`), "Fetch now" (optional; it ignores cadence and backoff; "Fetching…" while any fetch or archive job of the source runs, also one started before the sheet opened) and the on/off switch; a broken source the source doctor looked at shows a warning notice under the health summary, "This source stopped working." with "INSIGHT found a replacement: Arena blog (https://arena.ai/blog/feed.xml)" or "… Follow arena.ai/blog: 76 articles", **Switch** (the source keeps its name, tracks and posts; the next fetch reads the new address) and **Dismiss** (until the next failure streak), or "INSIGHT looked for a replacement 2h ago and found none."; a source whose pages INSIGHT reads worse than they show adds one quiet `text-fg-2` line under it, "Pages from this source lose most of their images (5 of the last 8)" or "Pages from this source often open with a very short block, maybe a menu left in (6 of the last 8)", from its newest page reads, issue 0032; then Name, Tracks, Show in Main feed (off keeps it fetched and readable on its own page), Watch for changes (only a source whose posts are pages, page watch or a site adapter; off by default, saves instantly; decision 032), how often it is fetched and why in plain words ("Fetched every 1d (new source, until it has 3 dated posts)") with "Set your own (hours)", Fetch delay; Save (for Name and Fetch delay; the rest saves instantly, so there is no Cancel: the sheet closes with × or Esc); Delete. How many posts one fetch reads and the order sources are fetched in are INSIGHT's own per kind, not settings. Below them, **Archive**: Stored and At the source (worded by what the source can tell, with `measured 3d ago` or `not measured yet`), then Plan, which measures the source and says where the archive continues from and how much is older ("You have 120 posts, back to 3 Mar 2025. The archive continues from there: about 2,180 older posts · ~18m", or "… · size unknown" when the source reports no size); an archive fetches everything older than what is stored, jumping below the oldest stored post when the source allows it, so there is no count to choose. Run or Resume archive with a progress bar while it runs, then the last run's result; an archive a site paused by limiting us shows a warning notice, "Paused: reddit.com is limiting us", with Resume (it continues from the checkpoint); a source that cannot archive is one quiet line (a subreddit: "Reddit refuses archive requests for now"). A second archive of a source is refused while its first one runs. A source that is off or unavailable has no Fetch now, main feed, cadence or archive: one line says why ("Off: not fetched until you switch it on", or the reason it is unavailable with "add in Connections").
- **connections tab:** one row per provider with something to add (Substack, Telegram; Reddit and YouTube read public feeds and have no row) with glyph + word (`working`, `set · not tested`, `failing`, `incomplete`, `sign in needed`, `not set`); a row opens to its write-only fields (a set field shows `set · ••••a3f · updated <date>`, never the value), a Test button, Telegram sign-in, Substack how-to.
- **ingestion tab:** sub-nav `overview / archive / jobs / logs`. Overview: Scheduler (how often it checks, next tick, "Change interval"; its dialog's "Sync sources.json every cycle" warns that a source missing from the file is deleted with its posts), "Run due sources", Last run. A run report says what the run delivered, in words ("34 new posts from 5 sources", "Nothing new: 12 sources checked", "Nothing was due", "3 sources failed"), then the sources that delivered, each with its count and a link to read it, and the failed sources, one line each with the reason; no zero counts, no raw JSON. The scheduler wakes every `ingest_tick_minutes` (60) and fetches only the sources whose own cadence is due; a tick with nothing due is a cheap check with no request, so it leaves no job (the Scheduler line still shows the ticks). Archive: the catalog of enabled sources that can archive (a feed that lists no more posts than one fetch reads, and a kind this server cannot fetch, are left out; one fetch reads what the kind's fetches read, 20 for a feed) (glyph + word `archived` / `partial` / `not archived`, stored of available, `1,602 older posts not archived` (or `nothing older to archive`), `measured 3d ago` or `not measured yet`, a saved checkpoint), searchable; the picked source gets the sheet's archive controls plus Pacing (page delay, batch size, batch cooldown; blank keeps the source's own value), and the run shows in jobs. Jobs: the job history, each run worded by what it delivered; a job opens its report and its events, one line per source fetched ("r/viture: 3 new of 25 · 52 of 81 sources", with "· 2 of 3 pages lost most of their images" when articles read from their page did), per slow-down and per feed that moved ("Arena: feed moved, now following arena.ai/blog/feed.xml"). Logs: one backend log's last 200 lines, a log picker and Refresh; it refreshes every 30 seconds. Under every view, one quiet `text-fg-3` line with the running version (P11): `I.N.S.I.G.H.T. Mark IX v9.1 · b9fcc6e · 27 Oct 2026`; when the web app and the API differ, both and "out of step"; unstamped, `dev build`.

## States

- **dense:** 90+ sources in the flat list, a few failing and in backoff.
- **search-no-hits:** "No sources match" with "Clear filters".
- **bulk-selection:** several rows checked, the bulk bar showing.
- **source-sheet:** the sheet open on a source (`?source=<id>`).
- **connections-set / connections-unset / connections-expired:** providers working; nothing set; a failing test or a lapsed session ("sign in needed").
- **ingestion-partial-failure:** the last run report with some sources failed, each with its message.
- **scheduler-stopped:** the scheduler has not ticked: one clear warning line (P11).
- **ingestion-archive:** the catalog with a channel picked for a backfill, its checkpoint ready to resume.
- **ingestion-logs:** the application log's tail.
- Also: no sources yet ("No sources yet" + Add source), loading (eight-row skeleton), load error (`ErrorState` with Retry), a failed refresh with the last loaded list kept (warning `Notice` + Retry).

## Interactions & keys

- `j`/`k` move the active row, `x` select, `o`/Enter open the sheet, Esc clear the selection. Never inside a field, dialog or menu; single keys follow the reader's shortcut switch. Shift-click selects a range.
- Adding a source fetches it straight away (an enabled one): its toast goes from "Added — fetching now" to the run's result, so nobody waits for the scheduler.
- Deleting a source or a track asks first and says what goes with it (`ConfirmDialog`). New track and Rename are small dialogs.
- Switching tabs closes the sheet; a link out of the sheet ("add in Connections") switches tab.

## Worst cases

- Long or URL-only names middle-truncate with the full name in `title`; derived names via `sourceLabel()`.
- Counts and dates are tabular and never truncate; columns drop by width (the headers, kind and last post below sm; added and status below md, where the toolbar's "Sort:" button reaches every column's sort).
- A failing message of several hundred characters wraps in the sheet; in the run report it is one line, the full text in `title`.
- Hundreds of sources: groups collapse; headers stay sticky under the toolbar.

## A11y & motion

- Roving focus: only the active row's controls are tab stops. The column headers are buttons with a pressed state, named with their direction (`Sort by Posts, descending`), not `aria-sort`: the list is not a table. Status is glyph + word everywhere. Checkboxes and switches carry labels; the track menu is a `menu` with `menuitem`s.
- Tabs never animate; the sheet slides 260ms in / 200ms out and fades under reduced motion; dialogs scale from 0.97 (P12).
