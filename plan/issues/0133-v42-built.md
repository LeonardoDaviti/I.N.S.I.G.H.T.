## What was built
1. **The arm `ent-v4.2`** (`schemas.ENTITY_ARMS`, beside ent-v3 / ent-v4 / ent-v3-6k): 6,000 characters,
   `ENTITIES_V4_SCHEMA`, **the citation rule off** (`citations.py` is never called for it).
   `guides/ent-v4.2.md` ← the lab's `ent42_extract.md`, byte for byte (md5 `81c469a1a9a0dce9128e2672e3c40089`).
2. **The second question, kind `cite`** (guide `cite-v1` ← `ent42_cite.md`, md5 `4e46eca8e320f831d88dde2130bc681a`;
   a test checks both md5s).
   - Input: `post_block(p, 12 links, 6,000 characters)` (`ent42.cite_input`).
   - Schema (`schemas.CITE_SCHEMA`): type document / org / person; role source / recommended / subject; `by`; at most
     30. `validate._cite`: an org or a person is a source only; every span occurs in the input.
   - **Planned only for cue posts** (`ent42.plan`, `tasks.PLANNERS["cite"]`, windowed like entities): only while the
     switch is on ent-v4.2, only posts with an ent-v4.2 entities task and no cite task, newest first. The cue rule is
     the lab's `entv42_run.cue` (≥ 800 characters with ≥ 2 distinct `CUES`; or an author-year citation, arXiv id or
     DOI in the first 6,000 characters (ent-v4.1's text forms); or one of the first 12 links with a document shape,
     `ent42.shape` = the lab's `entv42_rule.shape`). Non-cue posts are remembered per process, not re-read each lease.
3. **The merge** (`ent42.py`, the lab's `entv42_rule.finish` with the rule off): own-title documents dropped (main and
   cite), `cite_fix`, `merge_cite` (skips a cite `subject` document, a describing span (`name_span`), a document the
   main answer typed model / product / software / dataset / event / law / other / place; adds the rest the main
   answer lacks). The added ones are stored in the post's ent-v4.2 set with `mx_mentions.rule = 'q2'` and the cite
   call's id.
   - **Either order:** a main answer merges the post's answered cite answer at once; a cite answer after the main one
     appends its new entities (n after the last); a cite answer before it waits. Both take a per-post advisory lock,
     so parallel calls can't lose one.
4. **The rule is off** for this arm: no `rule = 'citation'` row is written under ent-v4.2.
5. **The page.**
   - The post panel: "· second question" on q2 entities; ✓ / ✗ on every new entity (a document, a `source`, a
     `recommended`, any q2), with "you said …". `POST /api/markx/posts/{id}/mentions/label {guide, n, answer}`.
   - Labels: `mx_labels` item kind `mention` (a = the post, b = the mention's call, note `guide:n`, the newest row
     counts). **Migration 0087** only adds `mention` to the item_kind CHECK (idempotent, 0081's way).
   - The Worker tab (/markx): the ent-v4.2 radio carries "lab: 89–93% precise, finds about 62%; post hoc", and under
     the switch the running precision from the labels ("N of M new entities right: P% (95% from L to H)", the second
     question's alone, and "leaves Shadow at 100+ labelled with the lower bound ≥ 85%").
   - Frontend calls are in the Mark X chunks (`request()` in MarkXPanel / MarkXOverview), not `api.ts`.
