### C1. Discover and origins use one title rule
- **The rule** (`story_rules.origin_title`, now for Discover's articles too), in order:
  1. **the page's own words, as a stored post quotes them** (`post_links.quoted_words`): a quoted tweet's text (Nitter's `<blockquote>` with its `<footer>`), and a link preview's title (the Telegram bridge's `<blockquote cite>`: site, bold title, description). A preview titled by an account (`(@name)`: "Claude (@claudeai) on X", a Mastodon toot) is a post's, so its description, the post's text, is used; a preview that only repeats its site's name gives nothing. The words become a title as the reader titles a post's text (`display_title`); the words most posts quote win;
  2. link words 2+ voices agree on (0068);
  3. link words the slug confirms (0068);
  4. **a link post's title**: a Reddit or HN post with fewer than `LINK_POST_MAX_WORDS` words of its own (0050's share rule) whose one kept link is the page;
  5. the slug made readable (0068), **without a leading id (5+ digits) or date**; a short number stays ("16 charts that explain the ai boom", "2025 ai index report");
  6. one voice's link words that read as a title; else the address.

### C2. A fetch job orphaned by a restart is closed
- **The code path:** the API's jobs (`trigger = 'manual'`: Fetch now, archives, comments) run in its process (FastAPI background tasks); the scheduler's (`'scheduler'`) run in the ingestion container. A row is inserted `running`, and `finish_job` sets it when the run ends. Nothing closed a row whose process died: a container stop is SIGTERM, then SIGKILL after Docker's 10 s (no `stop_grace_period`), and a fetch run takes minutes; the scheduler only finishes the tick it is in. `prune_job_runs` deletes rows after 30 days. The top bar (`runningFetchJob`) and a source's Fetch button read any `running` fetch job.
- **The server can hit it:** yes, on any deploy, reboot or crash during a run. The server copy (dump 2026-10-30) has no `running` row. The lab's one (`18b2d8e3`, SemiAnalysis, manual, started 2026-10-30 21:31) is the dump catching a run, and the lab API's start left it running, which shows the path.
- **The fix** (`OperationsService.close_interrupted_jobs(trigger)`): at the API's start (`lifespan`, before any request) its `manual` jobs still `running`, and at the scheduler's start its `scheduler` ones, become `interrupted`, with `finished_at` and the event "Interrupted by a restart". Each process closes only its own, so restarting one never closes the other's live run. The job list shows the job as failing (`jobGlyph`).
- **On the lab copy:** 1 closed (`18b2d8e3`), 0 scheduler jobs.
- **Tests:** a manual job closed with its event; the scheduler's left running until the scheduler starts; a finished job untouched; `jobGlyph('interrupted')`.

## Left open: C
- **Tweets linked only by a handle** (768 of Discover's 1,382 X articles show the address): no stored post quotes them. A tweet's text needs the tweet (fetching it, or following the account).
- **Lower-case slugs** stay when nothing else names the page ("Ecdsa curve origins"; 68 of 230 other 2+-voice origins are untitled). The page's own title needs the page (full text of outside pages, or Mark X).

Dropping a trailing site name when it is the preview's `<cite>` site would be one rule; not measured.
- **A Telegram post's preview** is titled by its channel's name (no `(@name)`), so an outside t.me post would be titled by its channel. None is an origin or a Discover article on the lab.
- **A link post's title is the poster's:** on Reddit it is usually the page's title, sometimes editorialized ("Decision model trained in ~2 mins on a single DGX Spark!" over the slug's "Train your own decision model with unsloth").
- **C2 with more than one API worker** (`API_WORKERS` > 1, not the default): one worker's start would close another's running manual jobs, since they share `trigger = 'manual'`; `finish_job` still sets the right status when that run ends.
