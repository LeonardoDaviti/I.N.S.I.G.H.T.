## A. A light API (built after the memory analysis lands)
- **The case:** after its first start the API holds 926 MB at idle on the lab (41,637 posts). A full story job peaks at about 500–780 MB, and each run after a fetch spends about 6 s over the whole database.
- **Decided:** the approaches the memory analysis measures and recommends, then:
  1. **An incremental story job.** New posts mark what they touch: the pages they link, their title and name keys, the stories holding those. Only that neighbourhood is regrouped. A rule change (a new stamp, 0071 B1) rebuilds in bounded batches in the background.
     - The full rebuild stays the oracle: the incremental result must equal it, tested on the lab copy.
     - Classics' and Discover's counts update by the delta, not over every link.
  2. **Stored connections:** a `post_edges` table (from, to, kind, weight, evidence, rule stamp, a verdict column for Mark X). Stories are derived from it, and story ids stay stable when an earlier post joins. The reader is unchanged.
  3. **Fewer writes:** link reading's pending mark moves to its own small table, so updates don't rewrite all 19 `posts` indexes (on the copy: 33 → 17 s, 1,167 → 374 MB of WAL). The search refill skips unchanged rows. The two unused indexes go. The boilerplate step uses the window-function rewrite (1.1–1.3 s → 0.6 s, same rows).
  4. **Smaller answers:** Discover and `/api/sources` stop sending 1.8–2 MB per open (paged, or only the fields shown). The unread counts stop scanning `posts` twice a minute per tab.
- **Done when:**
  - idle, peak, job time and WAL are measured before and after on the same copy, back to back;
  - stories, News, Classics and Discover are identical, row by row, between a full rebuild and the incremental job;
  - growth is re-measured at 25%, 50% and 100% of the copy.

## B. Rows that read right (v9.13 review)
1. **A quote card isn't the post's words.**
   - The byline ("Name (@handle)") and Nitter's footer address leave titles and text: 103 titles, 2,423 posts.
   - A post with no words of its own, which only quotes a post in its own story, is no line in trees, News or the thread page (71 replies).
2. **Telegram titles end where the headline ends:**
   - run past the headline because line breaks were lost (667): read the HTML's line structure;
   - cut at a bold tag's space (272);
   - the bridge's "[...]" kept (87);
   - cut at "т.к." or inside brackets (112 + 28).

   Fix each class, measured.
3. **A link post opens its article.** A Reddit or HN post whose body is only the aggregator's footer ("submitted by … [link] [comments]", hnrss's lines) shows "Read the article ↗". It is titled by the linked page when that page is stored or quoted. 1,085 Reddit posts carry the footer; 17 are nothing else.
4. **A title doesn't end in an address** (563), and isn't only "paper: https://…" (115). A label line ("paper:", "Download:") ends the title (211).
5. **Labels that agree:**
   - "covered by 1 · A, B" (99 stories) is fixed;
   - "629 in News" says what it counts, or matches what's shown;
   - an interrupted job shows its source's name, not a raw id, and how long it ran, not "25h 18m";
   - a single-topic post isn't labelled a roundup.

## C. Safety
1. **The source doctor checks before it offers a Switch.**
   - A server error (5xx) isn't "moved".
   - A candidate feed is offered only if it holds the source's own recent items (the same addresses or titles).
   - The sheet previews the candidate's latest titles before Switch.
   - Expected: Hacker News (HTTP 502) is offered nothing; `hnrss.github.io/updates.xml` never appears.
2. **Avatar lists aren't the article.** A run of small images linking to profiles, such as an upvoters list, leaves the full text: the Hugging Face blog's 6–22 avatars before its words.
   - Measured on the page corpus (0032/0053): no expectation that passes today may fail.
   - Then, without fetching, record what `repair_full_text --dry-run` lists for the Hugging Face blog, and note in `DEPLOYMENT.md` that the repair is safe to run.
3. **Imports only add, and removed sources stay removed** (owner).
   - Importing a file adds missing sources and never changes an existing source's on/off.
   - Removing a source remembers it (its address and when), so an import never brings it back. Adding it again from the UI forgets that.
   - Tests: an old file with a removed source and a flipped switch changes nothing; re-adding from the UI works.

### C1. The source doctor checks before it offers a Switch
- **Built:**
  - `failure_signal` reads HTTP 5xx and timeouts as `server_error`. The doctor records `{replacement: null, server_error: true, note: "server error, not moved"}` at once: no request, nothing offered, and the offer stored before is replaced. The health row shows no finding for it, as for "working again".
  - A candidate at another address (a feed, a blog page, the section) is offered or switched to only if it holds the source's own items: one of its items has the address (`normalize_url`, as the saver compares) or the title (`title_key`, as the story job compares) of one of the source's latest 50 stored posts. The finding carries `shared` (how many) and `latest` (its first 5 titles). The first feed that holds them wins, not the first found. A source with no stored post can be offered only its own address read as a page (0036's dry-run case of a page-only site still holds).
  - An offer stored before this check (no `shared`) is not offered: the lab's Hacker News row now reads `replacement: null`.
  - The feed finder keeps its items' titles (`Feed.titles`). An HTTP error whose body is a web page reads as its status line (`HTTP 502 while fetching …: Bad Gateway`), not the proxy's HTML.
  - The sheet lists "Its latest posts" (the 5 titles) above Switch.
- **Tests (recorded answers, `NeverOfferedTests`):** a 502, a 500 and a timeout offer nothing and make no request; HN gone (404) is still offered nothing, since the changelog holds none of its items; a same-site feed without the items is never switched to, and the next one that holds them is; a title at a new address counts; a page holding none isn't offered; no stored post means no other address; a pre-0072 offer is hidden. The 0036 tests now carry stored items; the 500 case moved to a network error. `replacementNotice.test.tsx`: the preview.
- **Expected, met:** Hacker News (HTTP 502) is offered nothing, and `hnrss.github.io/updates.xml` never appears.

### C2. Avatar lists aren't the article
- **Measured first:**
  - **The 7 stored Hugging Face bodies were read by the server's reader before 0053** (fetched 27-29 Oct; 0053's rules landed on 30 Oct). Re-read by main's reader (the stored body as the page), all 7 already lose their avatars before the words (6 → 0) and at the end. The corpus's real Hugging Face page (26 avatar items) already read with its 1 image on main. The planned repair on v9.14 is therefore safe for the avatars. The review's "likely the same" was the older reader.
  - **What main still got wrong:** `strip_html` ended a tag at the `>` inside `class="max-md:[&amp;>a]:hidden"`. So the heading-repeats-the-title check never matched (2 of the 7, re-read, still opened on their title), and the stored text opens `a]:hidden">`.
- **Built:**
  - `strip_html` (the reading path, not the content hash's `decode_first`) reads a tag past a `>` in a quoted value, and drops comments. A quote counts only after `=`; a tag it can't read ends at its first `>`, as before.
  - The reader drops a run of 3+ list items, each only a picture linking to a page, wherever it sits (`_linked_picture`). It never drops a picture declared larger than an icon, nor one linking to an image file (a gallery).
- **On real data:**
  - The page corpus: every expectation as before (56 pages, the same 16 known gaps). Only the Hugging Face page changes: it loses its repeated title heading.
  - The picture run: of 2,039 stored bodies with a pictured list item, only the 7 Hugging Face bodies hold one. Of 40,963 stored bodies, 130 read differently under the new tag rule, each kind checked better: commented-out HTML (a blog's hidden bonus notes, a draft section), alt text holding `-->` and attribute tails (`role="math">`) no longer leak into the text. Stored text changes only when a post is saved again.
  - Re-read, the 7 Hugging Face bodies open on their words, not their title.
  - The stamps (stories, stored bodies, addresses) are unchanged, so the first start rebuilds nothing.
- **The dry run, nothing fetched:** `repair_full_text --dry-run --source <Hugging Face blog>` lists **244** posts on the lab copy and **245** on the server copy, all to read, none skipped. The whole dry run: 5,516 posts on 320 sites (lab) and 5,588 on 319 (server). `DEPLOYMENT.md` says the repair is safe once the server runs v9.14 or later, and not before.

### C3. Imports only add, and removed sources stay removed
- **Built:**
  - `removed_sources` (0056): Remove in the app (`SourcesRepository.delete_source`) remembers the platform, the address and when. A Switch remembers the address the source left, since an old file naming it would otherwise add a second, broken source. Any add forgets the address (`insert_source`).
  - `import_json` adds only the sources the database lacks, on or off as the file says. It never changes an existing source's on/off and never adds back a remembered address. Those count as `removed`, not `skipped`, so a start doesn't exit 1.
- **Tests:** the fake service (a removed source not added back, a new one added off); on the database, an old file with a removed source and a flipped switch changes nothing; `POST /api/sources` re-adds and forgets, and a second removal is remembered again; the `DELETE` route remembers; a switched-away address isn't added back.
