## A. A light API (built after the memory analysis lands)
- **The case:** after its first start the API holds 926 MB at idle on the lab (41,637 posts). A full story job peaks at about 500–780 MB, and each run after a fetch spends about 6 s over the whole database.
- **Decided:** the approaches the memory analysis measures and recommends, then:
  1. **An incremental story job.** New posts mark what they touch: the pages they link, their title and name keys, the stories holding those. Only that neighbourhood is regrouped. A rule change (a new stamp, 0071 B1) rebuilds in bounded batches in the background.
     - The full rebuild stays the oracle: the incremental result must equal it, tested on the lab copy.
     - Classics' and Discover's counts update by the delta, not over every link.
  2. **Stored connections:** a `post_edges` table (from, to, kind, weight, evidence, rule stamp, a verdict column for Mark X). Stories are derived from it, and story ids stay stable when an earlier post joins. The reader is unchanged.
  3. **Fewer writes:** link reading's pending mark moves to its own small table, so updates don't rewrite all 19 `posts` indexes (on the copy: 33 → 17 s, 1,167 → 374 MB of WAL). The search refill skips unchanged rows. The two unused indexes go. The boilerplate step uses the window-function rewrite (1.1–1.3 s → 0.6 s, same rows).
  4. **Smaller answers:** Discover and `/api/sources` stop sending 1.8–2 MB per open (paged, or only the fields shown). The unread counts stop scanning `posts` twice a minute per tab.
- **Done when:**
  - idle, peak, job time and WAL are measured before and after on the same copy, back to back;
  - stories, News, Classics and Discover are identical, row by row, between a full rebuild and the incremental job;
  - growth is re-measured at 25%, 50% and 100% of the copy.

## B. Rows that read right (v9.13 review)
1. **A quote card isn't the post's words.**
   - The byline ("Name (@handle)") and Nitter's footer address leave titles and text: 103 titles, 2,423 posts.
   - A post with no words of its own, which only quotes a post in its own story, is no line in trees, News or the thread page (71 replies).
2. **Telegram titles end where the headline ends:**
   - run past the headline because line breaks were lost (667): read the HTML's line structure;
   - cut at a bold tag's space (272);
   - the bridge's "[...]" kept (87);
   - cut at "т.к." or inside brackets (112 + 28).

   Fix each class, measured.
3. **A link post opens its article.** A Reddit or HN post whose body is only the aggregator's footer ("submitted by … [link] [comments]", hnrss's lines) shows "Read the article ↗". It is titled by the linked page when that page is stored or quoted. 1,085 Reddit posts carry the footer; 17 are nothing else.
4. **A title doesn't end in an address** (563), and isn't only "paper: https://…" (115). A label line ("paper:", "Download:") ends the title (211).
5. **Labels that agree:**
   - "covered by 1 · A, B" (99 stories) is fixed;
   - "629 in News" says what it counts, or matches what's shown;
   - an interrupted job shows its source's name, not a raw id, and how long it ran, not "25h 18m";
   - a single-topic post isn't labelled a roundup.

## C. Safety
1. **The source doctor checks before it offers a Switch.**
   - A server error (5xx) isn't "moved".
   - A candidate feed is offered only if it holds the source's own recent items (the same addresses or titles).
   - The sheet previews the candidate's latest titles before Switch.
   - Expected: Hacker News (HTTP 502) is offered nothing; `hnrss.github.io/updates.xml` never appears.
2. **Avatar lists aren't the article.** A run of small images linking to profiles, such as an upvoters list, leaves the full text: the Hugging Face blog's 6–22 avatars before its words.
   - Measured on the page corpus (0032/0053): no expectation that passes today may fail.
   - Then, without fetching, record what `repair_full_text --dry-run` lists for the Hugging Face blog, and note in `DEPLOYMENT.md` that the repair is safe to run.
3. **Imports only add, and removed sources stay removed** (owner).
   - Importing a file adds missing sources and never changes an existing source's on/off.
   - Removing a source remembers it (its address and when), so an import never brings it back. Adding it again from the UI forgets that.
   - Tests: an old file with a removed source and a flipped switch changes nothing; re-adding from the UI works.

## Also in this issue (story job, built with A)
- **"First" only when it's true:** a post is marked first only when its trustworthy time is the earliest among the story's voices. On the lab, HN's S-1 post at 13:04 says "first" though a Telegram post came at 13:01 (42 of 260 page-rooted stories). A date-only post never sorts first at 00:00 (59 stories).
- **A thread is one item in News and trees:** one line, "Thread · 9 posts", not reply by reply. Terra's News row lists 9 of its 19 lines from one thread.
