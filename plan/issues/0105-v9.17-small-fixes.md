# 0105 — v9.17 small: Classics on a source's page, the export's estimate, the source list's size

Status: **built** 2026-11-05 on `issue-0105-small`, not merged (Built, below); spec 2026-11-05, from the v9.16 reader review (private review W6, W8, Memory and load).

**Constraints:** download nothing; no real names in committed files; nothing merges unless `scripts/realdata-check.sh` passes; the bundle gate.

## Wrong today
1. **Classics on a source's page say "Covered" and hide the source** (144 of 644; v9.15 W11, unchanged). A source cites a classic, it doesn't cover it.
2. **The export's estimate is 55% high:** it says 376 MB and 42 s; the export is 243 MB in 28 s. It counts the tables' stored size, dead space included.
3. **`GET /api/sources` is 1.8 MB**, 98.7% of it each source's archive history in `settings`, which the list doesn't show.

## Decided
1. On a source's Classics tab: "Cited it" (or the role it has), and the source named first among the voices.
2. The estimate from live data (e.g. `pg_column_size` over a sample, or the last export's real size when there is one, stored with its time), and it says which.
3. The list answer leaves out the archive history (kept in the database — keep everything); the source's own page or archive panel reads it where it is shown. Measure the answer's size and time before and after, and check every reader of the field.

## Done when
- Frontend tests for 1; backend tests for 2 and 3; the bundle gate passes.
- Measured on the lab: the estimate within 15% of a real export, the list answer's size before and after.
