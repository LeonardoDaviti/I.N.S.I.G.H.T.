## Wrong in v10.0.2
1. **After a long hang of both API processes, one comes back at its open-files limit and stays there** (W4).
   - The review: a 15-minute hang (past the watchdog's cap) ended with 2,096 "socket.accept() out of system resource … [Errno 24] Too many open files" in one second. One process held 1,006 sockets against 1,024 (854 in CLOSE_WAIT), still 7 minutes later. Then a 200 s spin of the other process: 195 of 195 background probes timed out, 11 of 40 `/api/version` from inside timed out at 5 s, the watchdog failed 3 checks in a row.
   - Cause: during the hang the connections pile in the shared listen queue (uvicorn's backlog 2,048); coming back, one process accepts them past the container's default soft limit (1,024). At its limit it can neither accept nor open a database connection, so its queued requests drain slowly or never.
   - `docker/start-backend.sh` says "uvicorn's supervisor pings each process and replaces one that stops answering". uvicorn 0.54 pings a thread of the process (`always_pong`), which answers while the event loop spins, so it replaces only a process that exits. The review: the same pids through hangs 1–4.
2. **A stale restart request is acted on at the next start** (M1). The API stopped for 2 minutes (`docker stop`): the watchdog failed 4 checks, wrote the request and recorded "The API was restarted at 11:42", though nothing had restarted. At `docker start` the supervisor took that request and killed the API 4 s into its start; the record counts toward the 3-an-hour cap.
3. **Restart records show UTC beside the page's local times** (W7): "The API was restarted at 10:53 after 2 min of no answer" over "11/6/2026, 2:53:23 PM"; "so no more until 11:40" (local 15:40). `api_watchdog._hm` formats in the container's zone, UTC.
4. **"The last decision run stopped …" never shows** (W6): `DecisionJob` checks `wanted_at` before `last.ok === false`, and a stopped run is always wanted again (`_finish(again=True)`). After the review's 174 s stop the tab said only "A decision run is asked for". Also: the log says the retry is "at the next look" (it waits for the 5-minute gap), and `stopped_before` keeps only the last word ("decisions").
5. **Mark X News tags a row NEW with no answers** (W5, 1 of 121 rows): a model release's row of 3 sources, the row 0111 Decided 4 removed from Mark IX's News (its first post is 6 Oct, before the window). Mark X read the posts of no story from the window's start only (`markx/news.window_posts(cur, since)`), while Mark IX's code reads them from `NEWS_EDGE` (48 h) before it, so Mark X's copy of the row began inside the window.

## Decided
1. **Open files:**
   - compose sets `ulimits: nofile: 65536` on `backend`, and the API supervisor raises its own soft limit to the same (never past the hard one) before uvicorn starts, so a `docker run` without compose's limit gets it too;
   - uvicorn runs with `--backlog 256` (was 2,048) and `--limit-concurrency 512` (503 at once past it), overridable by `API_BACKLOG` / `API_LIMIT_CONCURRENCY`;
   - the supervisor counts each API process's open files every 5 s; one at 90% of its limit at 3 looks in a row is ended (SIGKILL) and uvicorn starts another in its place (with one process, the container restarts);
   - the start script says what uvicorn does: it replaces a process that exits (or whose ping thread can't answer), never one whose event loop is stuck; only the watchdog's restart or the open-files guard ends that.
2. **A stale request is never honoured:**
   - the watchdog's check tells a missing API from a hung one: the connection refused (nothing listens: stopped, or starting, migrations included) or the name unknown (compose's DNS drops a stopped container) is **absent**: no failure counted, no request, no record. A hung event loop keeps its listening socket (the kernel accepts, nobody answers) and a full queue drops the handshake: both are timeouts, and count;
   - the door (in the API supervisor) sets aside a request written before the supervisor started, or more than 60 s old (it looks every second), renamed `.stale`; it tells the judge, whose record gets "Not restarted: …";
   - `./update`: the build runs while the old containers serve; `up -d` recreates the API and ingestion; the new API is absent while it migrates (counts nothing) and any request left from before is older than its start (ignored). So a deploy never ends in a kill of the fresh API.
3. **Times in the reader's zone:** the record's message has no clock time ("The API was restarted after 2 min of no answer"; "… so no more for 40 min …"); the payload holds `at` and `until` as ISO UTC (and `restarts`), and the job list writes "restarted at 14:53", "no more until 15:40" in the browser's zone. A record written before keeps its message; the page writes it from its start time (and "for up to an hour" for a give-up, whose end it didn't store). The backend stores UTC.
4. **The stop line:** shown under the asked line whenever the last run stopped (`last.ok === false`); it says "It runs again within 5 minutes", as the log does; `stopped_before` keeps the stage's whole name.
5. **Mark X News' edge is Mark IX's:** Mark X reads the posts of no story from `NEWS_EDGE` before the window (`window_posts`), so a row an earlier post begins is no row of the window, as in Mark IX.
