## Real bugs behind the words
1. **Archive catalog and its refusals.** The catalog lists every enabled source, including the 38 that can't archive ("No archive" only once opened). The refusal "every fetch already reads up to 50" is false: `get_source_by_id` reads no settings (`repo_sources.py:23`), so the check always uses 50, while RSS fetches 20. A feed listing 30 posts (Solos Glasses Blog) has 10 archivable posts but is refused (`source_fetch_service.py:92-160`). **Fixed** (e7cfa30): the check reads the merged settings, floored like a fetch (RSS 20, YouTube 15); a source that can't archive leaves the catalog.
2. **"Max posts per fetch: Not enforced yet"** is false: it is enforced (`ingestion/schedule.py:184,286`, `runner.py:313`; live 20 RSS / 5 YouTube / 25 Reddit). The field is disabled, yet the sheet's Save sends it (50 when unset, `SourceSettingsEditor.tsx:117,206`) and templates send theirs. Decide: a real editable setting, or no field and stop sending it. **Fixed** (ddc6af4, 2ac0156): no field in the sheet or Add source, nothing sends it, and the API no longer accepts it. Values stored by old sheet Saves (50) stay until repaired.
3. **A track's "In main feed and digest" ✓** reads the track's own stored flag, which nothing else reads (`main.py:806`); AI Papers shows ✓ while all 3 of its sources are out of the main feed (`SourcesConfig.tsx:282-287`). Derive it from the member sources (mixed when they differ). **Fixed** (3f115dc): the check is read from the member sources (✓ all, – mixed); the route no longer writes the track's flag and the UI no longer reads it (the column stays: generic folder create/update still carry it).
