## A. Your data can't be lost by a file
1. **The database is the truth for sources; `sources.json` is an export.**
   - **Today:** both containers mirror the file into the database at every start, and daily. A source missing from the file is deleted with its posts (up to 83 of 247 without warning). The file is in git, and the API rewrites it without a safe write.
   - **Decided:**
     - Adding, editing and removing a source write the database only. Removing happens only through Remove in the UI, as now.
     - The file is written as a backup export after each change: written to a temporary file, then renamed.
     - Importing a file (first install, or by hand) only adds and updates, and never deletes.
     - The file leaves git: untracked and gitignored, with an example file kept for new installs.
     - A missing, empty or broken file changes nothing.
   - **The server's deploy:** the server's file has local changes from the UI, so a pull that deletes the tracked file would refuse. `DEPLOYMENT.md` gets the steps: set it aside, pull, put it back, and the new code reads it once as an add-only import.
   - **Done when:**
     - tests: a file missing sources deletes nothing; a broken file changes nothing; an import adds; the export is atomic;
     - a dry run on a copy of the server data: 0 sources deleted, 247 kept.
2. **A start never fails for something non-fatal.**
   - A bad source entry, or two containers adding the same source, is logged and skipped.
   - `/health` makes one quick database query.
   - `update` lists the migrations it will run before running them.
3. **The API answers only the machine it runs on** (127.0.0.1 in compose), with the frontend's nginx reaching it on the compose network.
   - Check first that the owner's way in (`http://<serverip>:5173`) goes through nginx only. If anything calls the API port directly, record it and stop.
4. **One API worker, enforced:** the start refuses `--workers` > 1, with a message saying why. The architecture review lists six things that break with two.

## B. Versions that keep themselves
1. **No hand-bumped version decides whether derived data is fresh.**
   - **Today:** five stamps are bumped by hand (`RULES_VERSION`, `ADDRESS_RULES_VERSION`, `COUNTS_VERSION`, `STORED_BODIES_VERSION`, `search_vector_version()`). Two misses left 1,574 lab stories and 1,769 Discover address rows stale.
   - **Decided:** each stamp is derived from the rules it guards, computed at start.
   - **Measure** which way catches both past misses (0068's `site_of`, 0068's titles) without a full rebuild after a refactor that changes nothing:
     - (a) a fingerprint of the rules' output on a fixed, neutral sample of posts and addresses kept in the repo;
     - (b) a hash of the rule code;
     - (c) both.
   - Adopt the one that does, record why, and remove the hand constants.
   - **Done when:** tests show that changing a rule's output changes its stamp, and a pure rename doesn't (under the adopted way). The stale 1,769 Discover rows refill on the lab copy.

## C. One rule for each thing
1. **One addresses module.** "Site", "host", "publication" and "tweet" each have one definition, used everywhere: Python (three `_same_site` functions that disagree, the tweet pattern in 3 places, `"x.com/"+user` in 8) and the frontend (6 host helpers).
   - Where today's definitions disagree, measure on the lab which is right and record each change in what you see. `parsing._same_site` still treats `x.github.io` as `github.io`.
2. **The rule files split by job, with no change in output.**
   - `story_rules.py` (909 lines: stories, trees, origin titles, Discover) becomes stories, trees and Discover rules.
   - `news_rules.py` becomes names and Classics.
3. **One title comparison:** the five title-comparison rules (four in Python, plus SQL's `post_title_key`) become one, NFKC included, so the saver compares like the story job. Measure on the lab and record any change.
4. **Constants say why, and say it once.**
   - Each tuned constant names its measurement (issue and number) or says "not measured".
   - Duplicates merge: "30 days" ×4, `NAME_TITLE_DAYS = 32`, `SHORT_KINDS`/`HTML_KINDS`.
   - `INSIGHT_SYNC_SOURCES_EACH_CYCLE` is read by one parser.
5. **Tests that can't collide:**
   - each test run uses its own database (`run-tests.sh` creates and drops one; the name ends in `_test`);
   - one shared factory for posts and sources replaces the 4 factories and 11 insert helpers.
6. **Docs match v9.12:**
   - `BACKEND.md` (every route, including News, Classics and Discover);
   - `DB.md` (every table, through 0053);
   - README, QUICKSTART and FRONTEND (stories are back: trees, News, Classics, Discover);
   - the issues README's statuses;
   - the version line (`VERSION`) says the real release.
7. **Small leftovers:**
   - remove the cache-only folders `backend/fastapi/`, `pydantic/`, `psycopg/` and `dotenv/`;
   - list dead `.env` keys in `DEPLOYMENT.md` as safe to remove (names only);
